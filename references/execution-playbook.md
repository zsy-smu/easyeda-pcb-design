# 下一块PCB的执行手册

目标是接到任务后能自主推进到可编辑、可核对的交付，而不是每次重新摸索连接和脚本。这里是代理执行路线，不是声明已有万能自动布局/布线引擎。只读审查、局部改字取相关步骤，不启动整套新板流程。

## 1. 接任务后立即执行的动作

1. 读取用户的用途、输入/输出、接口、机械和交付要求，检查已有工程/资料。沿用已确认条件和授权，不重新问一遍“是否开始”。
2. 按[AI Bridge手册](ai-bridge.md)发现已连接工具/服务，取得真实工程与文档身份。没有连接时继续器件/电气/离线约束准备，只报告具体缺的连接动作，不虚构已在EDA画好。
3. 保存当前基线和已知布局，建立本次输出目录；现有工程不覆盖，复制/增量修改。长任务用[设计记录模板](../assets/templates/design-record.md)，记录最后一个已验证动作、文件和下一步。
4. 先完成电气闭合与关键器件确认，再进入原理图/PCB。用户说“其他自定”时自主决定可逆的实现细节并记录依据；实际负载、耐压、接口标准等影响可靠性的未知项不能凭空填成已确认。

一个合适的项目目录可用`inputs/、native/、layout/、gerber/、bom/、preview/、evidence/`；已有约定直接沿用。不为目录齐全先生成无内容的交付物。

## 2. 电路基础先落到可审查的数据

| 任务 | 应产生的实际结果 | 进入下一步前检查 |
|---|---|---|
| 需求收敛 | 输入范围、输出/峰值负载、同时工作、信号方向、机械限制、可改/不可改项 | 满充/欠压、电机启动、上下电与默认状态未被标称值掩盖 |
| 电源与功能框图 | 电源域、转换链、使能/保护、返回路径、处理器/驱动/传感器接口 | 功率预算不重复计数；地名不冒充隔离；电平兼容 |
| 关键选型 | 准确厂家订货号、数据手册、封装、库存/替代与手焊条件 | Pin1/脚号、热/额定/ESR/磁件、机械外形有依据 |
| 引脚分配 | 逐脚网络和保留/NC；启动、调试、时钟、复用冲突 | 不只给GPIO名称；电源脚/模拟电源/背板/壳脚全部覆盖 |
| 规则依据 | 铜厚/层叠、线宽、间距、回流与必要阻抗要求及来源 | 规则来自本板，未确定项保持待审；不把preset当标准 |

先读[electrical.md](electrical.md)相关小节。元件库查询获得的条目还要核封装和采购属性，不以“搜到了同名器件”结束选型。能用已验证的标准电路时沿用其**完整适用条件**，不沿用另一板的电压/电流/引脚默认值。

## 3. 建立器件和库的真实映射

每个物理器件保留`位号、Unique ID、Device/Library UUID、Symbol/Footprint UUID、实际引脚网络、准确料号、最大本体、来源`。这可以是项目已有JSON/CSV，不强制格式。归档后再建立内部别名映射，不能把全局UUID和包内ID混为一谈。

库选择顺序：准确厂家/供应商条目→检查符号/封装/本体→已有可信等效条目→有机械图依据的自建库。后两者明确为手工采购/占位，不带入借用符号的错误供应商号。完整Device里嵌入的Symbol和Footprint关联也要核对，不仅改PCB的Footprint字段。

按功能分页画原理图，小批放置/连接后读回逐脚网络并保存。网名相同但导线没有接到引脚不能通过；坐标一致也不能替代网表。有多个符号单元时按物理芯片分组。替换时按[器件替换](replacement-and-delivery.md)保存身份、恢复连接和属性，最后重开验证，避免自动重编号。

## 4. 导入PCB后先校准，再摆放

执行原生从原理图导入变更，读取完整差异。API只返回initiated时记录为“待应用”，不能跳到布局完成。应用后取得实际器件/焊盘/封装源与板映射。

校准至少覆盖：一个SMD器件、一个通孔/端子、一个带旋转或镜像的器件。将实际焊盘中心与原厂图、原生源对照，确认坐标、旋转、层、孔型和单位；模块/特殊封装还查隐藏定位孔/开槽。校准结果保留在任务记录，布局计算统一mm，写入时按接口转换。

原始横排/竖排和飞线是导入基线。先核元件总数、位置范围、板框与层数；如果所有坐标在板外或跨度明显不合理，先修数据适配，不继续批量缩放“摆整齐”。

## 5. 布局的实际推进方式

按[布局方法](layout-method.md)依次固定机械锚点、安排关键回路、再填普通器件。

### 第一轮：可安装

把板框、孔、边缘开口、接口入口/Pin1、按钮操作面和模块整体纳入硬约束。为电解、磁件、电阻、散热器使用最大本体，不用焊盘框冒充外壳。接插件的方向以实际插接形式校准，不将所有J/CN/SB/RV自动推到同一种边缘姿态。

显式本体与焊盘坐标均有可靠输入时，可调用`check_placement_collision.py`和`check_layout.py`粗筛；结果只覆盖已建模的几何。分离向量不是最终坐标指令，移动后重新检查邻居、板边和固定点。

### 第二轮：关键回路可走

围绕真实引脚安排：输入旁路—功率开关—续流—输出回流，驱动去回路，反馈/采样取样点，MCU每组电源去耦，时钟与模拟滤波。用少量试布线验证出口，不先把全部元件按网名聚在一起。

候选比较按以下顺序，先淘汰不满足者：

1. 机械、极性、接口方向、隔离/禁布及固定位置等硬约束。
2. 功率/反馈/时钟去回路径是否可实现，有无唯一细颈、穿地缝、危险绕行。
3. 普通信号的逃线、拥堵和预计跨层需求。
4. 在前面条件均满足时，优化长度、装配方便和图面整齐。

不要用一个总评分抵消硬约束失败。移动几颗0603后仍拥挤，就回到区域容量/功能组重排；不连续把电容、电感、接口都朝同一边推。改布局通常比反复修改路由网格有效。

### 第三轮：全板连贯

本体无冲突不等于可布线；局部可布也不等于整体能装。把候选放回最新全板，检查各组间走廊、地参考、线束/螺丝空间及板边。未经用户授权不通过加层、放大板框、改接口来绕过原约束。

## 6. 布线：生成候选、核几何、再写入

AI Bridge提供放件、改坐标、画段、过孔、铜区等原语，不等于具备避障/阻抗/差分/热求解的全自动PCB路由器。现有已验证的路由器可复用；否则按支持的网络类别显式规划路径，不能调用不存在的`pcb.autoLayout/autoRoute`宣称完成。

- 先布关键路径并保留，再布普通网络。对于多脚同网，设计去程/回程与实际分支，不能只把所有焊盘用最短生成树当成电源/地的最终方案。
- 离线检查包含有宽度的铜、焊盘、孔、实际FILL/POURED及每层避让；通孔连通两面。端点进真实焊盘内部，不以外包框相交当铜接触。
- 线宽按当前铜厚/电流/温升/压降与制造决定；过孔、辐条、端子和焊盘出口同步检查。脉冲、差分和安全间距需要各自依据，`calc_parameters.py`仅整理显式要求和稳态初估。
- 换层时安排合法的同网连接和回流，继续避开异网通孔；阻焊开窗不会改变铜层。没有连通能力验证时，不把减少飞线数量称为布通。
- 写入小批并读回网、层、宽、路径/孔。失败先分清整体未执行与部分成功，不重复放件或删陌生图元。全板Drc和独立检查失败时先定位具体对象，不通过放宽规则或断开网络清错。

更改已布线器件的事务：保存器件/相连铜基线→算新位置及本体/出口→重走受影响分支→按真实类型删除被取代旧线→重建受影响铜区→核实际连接和邻网→保存。其余区域的几何应等价；不同ID不自动代表不同铜。

若现有能力确实不能完成某类路线，继续完成可执行模块，并明确具体未连网络、阻挡和所缺能力；不把空白工程、未布线导入或预览图冒充成品。用户要求完整PCB时，持续修复范围内可解决的问题，不能为省事止于“给你一个方案”。

## 7. 铜、丝印和机械收尾

重建实际铜后检查浮岛、窄桥、板边与安装孔/垫片、回流连续性；独立实心FILL需要说明后续修改是否需脚本重建。层号从本版LAYER/SDK读，不照搬历史数字。

整理真正可见的接口功能、极性、方向和位号。顶/底视方向与实际Gerber分别核对；不要把所有隐藏采购属性显示成丝印。空间不够时优先保证接线和装配说明可读，不盖焊盘。预览保留铜区孔洞并标明是否重绘、底层观察方向及未显示的本体/层。

## 8. 交付验收要绑定同一个实际版本

| 检查 | 证据 | 不能用来替代它的东西 |
|---|---|---|
| 功能/启动/电平/选型 | 当前电路、准确手册、计算及必要仿真 | DRC0、目录里的器件名 |
| 逐引脚与实例/库/属性 | 原生网表、完整导入差异、归档映射；多单元合法分组 | 仅比较网名，或同名封装 |
| 实体铜与规则 | 当前原生DRC/未连接、受支持的实铜检查 | “API成功”“主干很宽” |
| 装配 | 本体/孔/插拔/工具空间与准确封装 | 焊盘不重叠或未校准3D |
| 文件 | 实际EPRO、Gerber字节、CRC、板框/层/孔、BOM与哈希 | hasFile、另一个版本的截图 |
| 往返 | 交付EPRO导入新副本，保存重开，原生差异/DRC复查 | 当时后台实例的DRC0 |

按各工具的独立输入契约运行检查：网表用`compare_netlists.py`，布局用`check_layout.py`，制造用`check_manufacturing.py`，归档/原生差异用`check_project_handoff.py`，证据与交付清单分别用`check_evidence.py`/`check_delivery.py`。未知格式/对象返回不支持，不能忽略后报全板通过。

API导出实际字节的命令见[AI Bridge文件操作](ai-bridge.md#5-单位结果和文件)。保存、工程导出和Gerber导出分别记录；按受影响几何决定复验范围。阶段文件与最终文件用新版本名，避免后续引用被悄悄覆盖。

交付入口应包含直接可导入的工程路径、两板映射（如为多板）、实际制造包、BOM、可读预览、已验证/未验证项。总ZIP另标为外层打包。不能在没有实板时承诺上电、温升、EMC或量产合格。

## 9. 让下一次任务可续接

每完成一个有用阶段保存，更新“当前有效文件、身份、已通过范围、剩余网络/待确认项、下一步”。中断恢复先核这些记录和当前文档，不重放全部旧写入脚本。

相同问题的修复应沉淀为窄工具或明确的适配规则，附输入契约和反例；不把完整私有工程、固定UUID/坐标或未经校准的缩放参数塞进skill。新工具应测试“会错误接受什么”和“会误拒绝什么”，并用真实工件作限定验证。连接、几何检查和电气知识互相配合，才能减少下一块板的反复试错。
