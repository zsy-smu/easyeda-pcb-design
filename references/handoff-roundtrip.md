# 完整工程的往返验收与导入差异

用于跨编辑器实例、原生源写入、换件、重新导入或“工程打开成了初始排列/DRC又报网表错误”。这不是所有小修改都重导入一次：在首次交付完整工程、修改实例/库关联、手工打包或更换客户端/主版本时执行；纯文字且证明其余内容不变时按受影响范围验证。

## 1. 保存、导出、用户打开是三个状态

记录编辑器环境、项目UUID、板UUID、文档类型、功能板名和版本。项目名、PCB1/PCB4等显示名都可能重复或颠倒；多板用“UUID→功能板→原理图→制造包”映射定位。连接断开或用户换了客户端后，重新读取身份，不继续把旧API指向的页面当作用户正在看的页面。

用户看到初始横排和飞线时，先比较当前源中的元件数量/坐标范围、板框、布线/过孔/铜区与已保存快照。不先归咎缩放、缓存、软件版本或“用户打开错工程”。未取得当时UUID/保存版本时，原因应保留未知；导出文件正常只证明该文件正常。

保存并重新打开实际交付的工程，核对：目标板仍有正确布局/库/网络，原生导入更新没有未解释的差异，重新执行网表一致性、未连接及DRC。当前API返回空错误不替代该步骤。需要用户执行唯一界面动作时，先完成可独立做的核对，说明具体待操作项，不声称已替用户验证。

## 2. 先区分能导入的工程与总交付包

`Delivery.zip`可能包含工程、Gerber、BOM和报告；它是外层打包，不因`.zip`被导入框接受就成为原生工程。提供可直接导入的`.epro`路径，外层ZIP中标清 `Native/*.epro`；导入报错先核对用户实际选的文件、压缩根目录和文件头，再讨论版本。

ZIP的CRC与库闭合只检查包的结构，不能证明客户端导入成功。不要仅改文件扩展名“修复”格式。使用复制导入的新工程做验收，保留原工程；不覆盖用户不明来源的当前项目。

## 3. 网表一致性不只是逐引脚网名

同时核对以下几类信息，不用其中一类通过代替全部通过：

| 信息 | 检查内容 |
|---|---|
| 逻辑连接 | 每个引脚、显式NC及网络；不把空网引脚并成一个网络 |
| 实例身份 | Unique ID、Channel ID以及多单元分组/关联；以实际保存源为依据 |
| 器件和封装 | Device、Footprint、Symbol及归档内部别名；设备元数据的封装与PCB实例的封装也要比 |
| 属性 | Name/Value、厂家/料号/供应商、描述及其它参与原生比较的字段 |
| 实体几何 | 焊盘ID、位置、孔、铜、器件位置及可见说明不因同步被意外替换 |

同名C0603不证明同一封装；系统库和个人库可能有字节相同的副本，但仍产生引用差异。先解析完整归档的别名/`source`映射，再比较封装源；相同文件字节可证明该副本的全部原生记录相同，不能外推不同文件一定机械不兼容。规范化引用时保留稳定引脚/焊盘对应与库闭合，不仅改显示名称。

替换器件时把旧料号/ESR/纹波等继承属性也列入审查。借用符号得到的Supplier Part不自动成为新器件采购号；占位值明确标注或移除，具体料号从已核对BOM回填。删除多余Value字段不等于删除元件，但要确保有效名称、数值、参数及BOM没有一起丢失。

### 多单元芯片的专门处理

运放/比较器的`.1`、`.2`等原理图单元可共用一颗PCB器件的Unique ID和位号。先按共同身份、Device、合法单元编号分组，再检查引脚并集与PCB。

- 不能以“一个PCB元件只对应一个原理图实例”为约束。
- 不能把后出现的第二单元覆盖掉第一单元，再误报Channel ID错误。
- PCB指向某个有效主单元可能合法；是否需要额外Link/多部件分组字段，以当前原生差异/网表为准，不能猜字段。
- 相同Unique ID但不同位号、器件或重复相同单元，仍需查错，不用“多单元”掩盖真正重复实例。

## 4. 用完整“导入更新”报告决定同步

只有一个“网表错误”时，先读具体原生差异；截图中的一屏列表不能代表全部。导出报告可能虽名为CSV却是UTF-16/tab分隔，且含空行和分组行；不能按逗号一刀切，也不能漏掉列表底部。

用 `scripts/check_project_handoff.py` 检查工程内部关联，并可加 `--changes 功能板名=报告路径` 汇总完整原生差异。它不操作编辑器、不修改工程，不能替代原生复验。

例如（路径按当前项目替换，不使用本案例私有文件）：

```powershell
python scripts/check_project_handoff.py project.epro --changes "Control=control.csv" --changes "Power=power.csv" --out handoff-check.json
```

功能板名须与EPRO的`boards`键相同。当前支持PCB/封装1.8、原理图1.1的JSON行式归档；其它版本/结构返回2，不当作空工程通过。输出`project-handoff-report/v1`绑定工程和差异文件哈希：0表示其静态范围一致，1表示有引用/身份差异或原生变更待审，2表示不支持或输入错误。工具承认合法多单元主关联，但不重建引脚网络、不推断原生Link属性，也不检查几何连通。它始终标明`nativeRoundTripVerified=false`。

参数工具当前输出`param-spec/v2`；旧v1里的“通用4mm脉冲/固定差分/间隙等于爬电”已撤销。`minTraceWidthMm`是显式项目最小值，稳态估算更大时不会压回下限；脉冲/差分候选需要`widthBasis`，间隙与爬电分别给值和依据。没有明确`slotWidthMm`不生成光耦槽要求。默认demo会以`exampleOnly=true`、退出1和待审清单返回，不能拿来直接生成当前板规则。

将变更分为：属性增删改；封装替换；实例增删；引脚/网络改动；规则或未知动作。属性缺失不是立即判“缓存”；出现元件增删、网络改动、未知封装几何时不能盲目全选应用。只有报告完整且所需变化均经核对后，才执行原生同步，保存并重跑检查。没有网络改名时通常不需要启用“同时更新导线网络”。

同步若改变了铜、焊盘、器件位置或铺铜，重新导出制造文件并复验；若仅元数据且几何等价，可沿用绑定相同几何的制造证据。归档几何比较只支持已解析对象，未知对象不能忽略。

## 5. 此次双板案例的结论与边界（2026-11-01）

历史NDT双板从2.2.40.1环境导出，用户在3.2.121重新导入。完整差异报告：控制板180项、励磁板147项，共327项；均为属性增删改或封装引用变化，没有报告元件增删或引脚网络变化。19项封装文件逐字节相同。U7为LM393双单元，原生报告要求补Link和多部件分组，不能改成只认第二单元。

用户应用两板原生同步后报告DRC均通过。这支持本次网表一致性问题来自元数据/关联不同步；未取得同步后的工程和重新导出的制造文件，不宣称已独立冻结该最后状态。原先“打开为初始排列”的具体UUID/保存版本没有取得，根因仍未证实，不能把它记成确定的版本兼容故障。

以上数量、UUID、板尺寸、电气参数不作为新项目默认值。证据是本机私有案例，仓库不包含原工程或用户报告；可复用的是排障步骤和通用检查器。
