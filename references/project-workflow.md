# 从需求到可复核交付

用于新板、跨多阶段改板或长任务续接。局部改字、单个接口调整只取相关步骤，不重新启动整板流程。已有记录可直接使用；没有记录时可复制 [设计记录模板](../assets/templates/design-record.md) 到项目输出目录，删去无关部分，不在 skill 内存放新项目状态。

## 1. 收敛需求，避免旧方案继续生效

复刻任务先确认是保持尺寸/接口的还原，还是允许替代器件的功能重设计。源工程、完整Gerber/钻孔、BOM、实物照片与通断测量分别能证明不同内容；照片不能证明隐藏层、器件底部连接、无标值元件参数或固件。建立待确认连接清单，已有可靠资料继续处理，不能把推测写成实测。此流程也适用于复刻，但不宣称历史工程已验证通用照片抄板能力。

从对话、当前工程和已有交付中恢复最新要求，区分用户确认、原厂依据、暂定假设、已被替代。用户说“好了”“已导入”时承接上次具体操作，读取目标状态，不能重新问一轮已回答的问题。

| 影响设计的条件 | 应记录的实际含义 |
|---|---|
| 输入与负载 | 输入最小/标称/最大电压及瞬态条件；各路持续、峰值、堵转电流与同时工作的组合；电机额定电压和驱动母线分别记录。未知电流不能以宣传额定值填补。 |
| 接口与机械 | 连接器确切料号或待实测规格、对插件、针序、插入方向、板边位置与公差、孔槽、外壳与高度。公母称呼或照片外观不足以确定封装。 |
| 成本与制造 | 用户已有模块的具体版本；手焊/回流、可接受封装、层数/铜厚/尺寸限制。免费打板活动按当时厂家规则核对每边限制；不沿用历史板的尺寸或价格。 |
| 电气边界 | 哪些接口是真正隔离；外部电源地如何接入；USB供电还是数据；启动方式、时钟精度、负载断开哪一侧；需要哪些保护。 |
| 交付范围 | 原理图、PCB、完整工程、制造文件、BOM、接口表、固件或实板测试分别是否在范围内。 |

只询问会改变方案或阻止安全定型的缺失项。可以独立完成的模块继续推进；电机电流未知时可完成已确定的控制部分和候选拓扑，但功率件、连接器、铜宽、保护和散热不能被标为已按目标电流定型。

需求修改后检查受影响链：电压/电流 → 电源与保护 → 器件/封装 → 铜与接口 → BOM/说明。旧候选标为被替代，避免用户改成成品模块后仍继续绘制裸芯片方案。

## 2. 先定电气关系与机械锚点

画线之前准备最小可用设计依据：

- 电源树列各路来源、额定范围、级联消耗、使能启动、回流和保护。级联下游功率计入上游，不能同时重复分配同一份电流余量。
- GPIO表写出完整MCU料号/封装、物理脚号、引脚名、复用功能和网络名。标记启动、调试、模拟、晶振专用脚及冲突；不把图面引脚顺序当物理脚号。
- 器件表区分已核对的原厂引脚/封装映射与采购编号。物料编号可有单独警告，实物引脚和额定值错误不能随之忽略。
- 固定板框、安装孔、接口方向、模块外形、天线/隔离/装配禁布区。底层或旋转器件的几何变换先用实际两个焊盘或孔核对。

需要时用 [电路功能审查](electrical.md) 逐类核对。用户或其他AI的点评是待核查意见：给出原厂依据、实际网络和适用条件，不能因为语气肯定就修改正确电路。

## 3. 原理图按模块完成并保存

先安排纸框、标题栏和功能区，再放器件与布线。每个模块完成后读回逐脚网络并核对目标，重复通道特别检查位号和独立信号。完整映射、NC与图面可读性分别核验，见 [原理图](schematic.md)。

对于“只整理排版”，保留原连通分区和电气属性；对于“改电路”，记录有意变化，按新目标核验。不能用旧网表必须完全不变的条件阻止必要修复。

同步到PCB前核对新增、删除、封装变更、引脚网络和板关联。导入发起、用户点击、实际应用、保存完成是不同状态；读回确认后才更新阶段。库属性重写、Channel ID和标签持久性问题按 [器件替换](replacement-and-delivery.md) 处理。

## 4. 布局、试布线、局部改善

先锁定真实机械锚点，再安排电源开关回路、去耦、晶振、模拟前端、驱动与通信，最后摆一般逻辑。布局依据实际电流和信号路径，不以原理图方框坐标或所有器件均匀排成网格为目标。

设置与本板对应的网络规则：电流/压降/温升、厂家叠层与最小工艺、差分阻抗及回流要求、隔离距离、手焊空间。数值来源要可追溯，未知时标暂定；不能从已经画出的宽度反推“设计规则”。详见 [PCB布局](pcb.md)。

矩形板且有完整、已校准的器件读回时，可用 [布局合同工具](layout-tool.md) 检查位置、面、接口全局朝向、器件禁布区及指定点间距。要求文件来自已确认需求，实际文件来自独立读回；异形板或未支持的对象继续采用相应原生检查，不把工具的有限范围扩成全板通过。

对密集或关键区域先试布线。失败记录具体网络与原因，例如接口逃线空间、走廊被封锁、参考层中断、禁布或孔铜距。按原因局部移动/转向或调整通道，再保留满足硬约束的结果；单纯减小剩余飞线总数不证明更好。

每次迭代保存可恢复的局部基线，比较功能/网络、锁定器件、接口朝向、隔离/机械禁布等硬约束，再比较未连网络、回路、过孔和可制造性。不得为了“全部连上”放宽规则、穿越隔离区或删除未知图元。自动路由器的完成率只是候选结果。

## 5. 按变化选择验证

| 本次变化 | 至少覆盖的复验 |
|---|---|
| 文字、功能框、图纸排版 | 可读性/遮挡、可见属性、保存；移动电气对象时另比逐脚网络与NC。 |
| 器件替换或移动 | 库/封装/关联身份、全部同脚实体焊盘、引脚网络、局部铜、机械与原生DRC；涉及标签持久性时保存重开。 |
| 线路、过孔、铺铜 | 真尺寸/层/网、实际填充、相关网络实体连通、间距/回流和原生DRC；不能只看边界框。 |
| 板框、孔、层叠 | 闭合轮廓、尺寸、孔槽、层及相关铜间距；若在制造交付范围，重新取得实际导出检查。 |
| 电源、驱动或接口功能 | 原厂条件、参数/引脚/电源域、受影响的连接与布局、BOM/接口说明；需要的模型仿真或测试另报范围。 |

“通过”要带目标文档、时间/文件哈希和检查范围。原生DRC、逻辑网表、实际铜、机械、导出内容、实板性能分开记录；空返回、false、未知格式和未执行不得当0错误。

优先调用现有只读工具：

- [网表比较](netlist-tool.md)：原理图/PCB逻辑分配；有两侧实体清单时比较同脚焊盘数量。
- [制造检查](manufacturing-tool.md)：对照独立要求检查实际ZIP的板框、层与逐孔几何。
- [布局合同](layout-tool.md)：对照独立要求检查适配后的有限机械几何。
- [证据时效](evidence-tool.md)：重用已有报告前，核对报告原有输入哈希、要求范围与可取得的文档身份；缺失绑定时重做相关检查。
- [交付清单](delivery-tool.md)：冻结已核验文件并检查后续字节变化。

工具未覆盖的特殊铜形状、内部库关联或仿真模型，报告缺口并取相应原生/原厂证据，不能靠生成一个报告补齐证明。

## 6. 保存、交付和长任务续接

完整任务的交付入口应让另一人找到目标板、完整原生工程、当前BOM与接口表、制造文件（若在范围）、预览及验证范围。页源不等于完整工程，离线重绘不等于编辑器截图。不同阶段资料可以保留，但入口只指向当前有效文件；不要靠文件名含final判断新旧。

结束一批或准备续接时更新少量当前状态：目标工程/文档ID、当前文件、最后一个已验证动作、未决问题、下一步具体动作、待用户完成的唯一必要操作。需要用户点击时给准确菜单/按钮和目的；收到完成回复后先读回，不重复索要截图或再次导入。

接口失败先确定是否已经产生副作用，再查目标、当前版本与已验证能力。相同症状无新证据时换诊断路径或最小替代，不循环重启、升级、导入。写入与编辑器状态操作由一个执行者完成；查手册、离线布局候选和独立审查可并行。

已定位且范围内可修复的问题继续处理。检查通过后无新变化就完成保存和交付，不反复重跑所有审计；未能完成的具体项和原因留在记录中，不能仅说“基本好了”。

## 7. 从经验更新skill

新经验先落到项目记录：触发条件 → 实际证据 → 最小修复 → 复验 → 版本/范围。可复用方法归入相应参考；稳定、重复的机械检查才提炼脚本，并用独立的正常/故障样例验证。

维护规则时优先替换失效表述、合并重复说明。历史索引见 [项目经验](experience-index.md)；历史报告只支持其对应快照，不自动成为下一块板的通过证明，也不把一次定制路由脚本宣传成通用自动布局引擎。
