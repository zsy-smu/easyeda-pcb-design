# 原生几何与检查差异

适用于排查“API/离线结果与嘉立创原生数据不一致”，不要求每张板执行所有步骤。

历史证据环境：2026-09-06，Windows、嘉立创专业版 3.2.121，本地桥接，磁盘扩展清单版本 1.2.4；清单版本不单独证明运行时加载版本。案例为 STM32 最小板，以 PCB5 为叙述代号。私人原工程、实物、原始快照和检查报告不随仓库发布；本文为经验摘要，不是公开可复现的板级验证记录。换环境先核验接口定义和一个真实对象，不能照搬单位、对象 ID、尺寸或修复脚本。

## 1. 建立可信的读回适配

同一对象的公开 getter、保存后的文档源、封装库图元并非总是同一表示。读回与预期冲突时，先比对对象身份和已知物理尺寸，再决定采用哪一层表示。

| PCB5 中实测的表示 | 本例解释与处理 |
|---|---|
| 全局 PAD / LINE / VIA 的位置、LINE 线宽 | mil；转换成 mm 乘 0.0254。全局 PAD 旋转读回与其他对象不必同单位，按字段核验。 |
| 保存源 VIA `centerX/centerY/holeDiameter/viaDiameter` | 本例也是 mil；41 颗最终过孔的真实尺寸从这些字段读取，并与全局 VIA ID 集合核对。 |
| 公开 VIA `holeDiameter/diameter` | 曾统一读出 12/24 mil，源里多数实际是 11.8110236/23.6220472 mil。不能把 getter 默认值当真实孔径。 |
| POURED `pourFills[].path.complexPolygon` 坐标与描边宽度 | 本例是内部 10 mil 单位，乘 **0.254** 才是 mm；不能沿用全局 LINE 的系数。`ARC` 的角度不乘长度系数。 |
| `pcb.getNetlist` | 本例是包含多块 PCB 的 JSON 字符串数组；按当前工程身份和元件/引脚集合选择。不能固定取某个下标或把整个数组当单板。 |

保存源的本机记录形如 `JSON头 || JSON体 |`，头包含 type/id；解析失败应报出未知记录，不悄悄跳过相关铜或孔。保存本次源与读回的时间/哈希，避免混用修改前后的几何。

### 局部修改也可能改到尺寸

本例对 VIA 只写 `net`，原生修改流程仍把 getter 的默认孔径/外径回写，实际源变成 12/24 mil。其他版本还曾影响阻焊属性。因此不要用“给所有过孔重写一次网络”作为通用刷新步骤。

需要改过孔时先保存真尺寸、网络、位置、类型、阻焊与锁定状态；优先使用经核验的精确修改接口，完成后逐字段检查。默认值造成的改动应恢复，或在当前任务允许且重新通过几何/制造约束后作为明确变更记录。本例最终 3 颗为 12/24 mil，其余 38 颗保留原尺寸；这不是推荐的统一过孔规格。

## 2. 原生报断开，而实际铜已经接触

先读具体 DRC 对象、层、网络和真实几何。存在真实间隙、错网、错层或漏孔时，修线路；不能先假定缓存错误。

PCB5 的最后四条 VBUS Connection Error 有以下证据链：

1. 新增走线/过孔在独立实际铜检查中已连通，但原生仍报四条线断开；重写过孔网络后错误仍在。
2. 保存源中过孔中心量化到小数点后四位 mil，新建线路的公开读回仍带更长小数。
3. 只把四条线的对应端点设为保存源中过孔的精确中心，几何位移小于 0.000003 mm；未改网、未放宽 DRC、未禁用规则。
4. 原生 DRC 随即清零，重建全部相关铺铜、保存后再次运行仍为零；最终实际铜检查仍通过。

这支持“运行时坐标精度/连接记录差异”的诊断，但没有证明所有内部实现原因，也不支持“所有断网都是缓存问题”。

**适用时的最小处置：**在已证明铜接触、且差值只属本次序列化精度的端点上，使用同一可信中心值对齐；保留修改前后数据，重建铺铜并同时复查原生 DRC、实际铜及孔距。不对全板坐标舍入、吸网格或移动器件。一次有依据的校正仍不解决时，继续查对象/规则或真实线路，不循环重写、重启、重新导入。

本例 `pcb.drawLine` 使用顶点坐标 mil，`pcb.placeVia` 包装器接受 **半径 mil**，再传给原生直径 API；迁移脚本时核对这一层包装，不把直径再翻倍。

## 3. 封装机械对象不能只从 PAD 表推断

USB-C TYPE-C31M12 的两个约 Ø0.6 mm 定位孔，是封装子对象 `FILL`、层 12；未出现在最初的全局 PAD/REGION 快照。原生 DRC 因它们与电源走线/过孔的间距报告了错误。

- 从完整原生封装源获取圆/槽几何，再按组件平移、旋转/镜像映射到板坐标；用两个实际焊盘中心验证变换。
- 孔铜距计算包含孔的实际外缘/相关描边，并与当前原生规则核对；本例使用的距离不自动成为另一板子的制造规则。
- 层 12 的 FILL 也可能表达其他几何，不能把所有多层 FILL 都解释为定位孔。结合库图纸与原生语义确认。
- USB 的一些顶层 POLYGON 焊盘 getter 曾带有非空 `hole` 字段；仍需按实际层、金属化和封装源确认是 SMD。否则会虚构跨层导通或钻孔。
- 外包框避让与实铜连通是不同证明。本例对四个特殊多边形焊盘还使用经验证的内接铜区复核，避免只碰到外包框就报连上。

`getDocumentFootprintSources` 返回空时可查当前工程的原生自动备份 EPRU。先核对时间、封装 UUID 与现有焊盘，不能默认为旧备份仍代表当前库。只有页源 `.epcb` 时，不称其为包含全部封装的独立工程包。

## 4. 覆铜与预览必须显示实际结果

创建 POUR 抛错时对象仍可能已经存在；先读回 ID、网络、层、边界及优先级，确认状态再决定补写。本例曾在异常后找到已经创建的局部 +3V3 POUR；盲目重试会重复创建。

边界存在不等于有铜。重建后按 `pourPrimitiveId` 将 POUR 与 POURED 对应，确认实际填充与连接方式。绘制实际数据时：

- `fill:true` 多闭环路径按奇偶规则处理孔洞；`fill:false` 的有宽度路径可能是热焊盘辐条，不能漏掉。
- 支持本次出现的直线、圆弧、多个闭环及单位；未支持的几何列明，不画空再报告通过。
- 每个铜区独立透明遮罩合成；检查孔洞没有擦除另一网络已绘制的铜。颜色区分只便于识别，不代替网名核验。
- 底层透视还是从底面观察要标明；预览没有元件本体/3D壳体时，不能据它宣布装配空间全部通过。

本例全局 String getter 列出了 99 个原本隐藏的 NAME/FOOTPRINT 等属性；原生 ATTR `keyVisible/valueVisible` 才说明它们不可见。保留这些属性，仅修改真正需要显示的位号和接口文字。文字包围框估计不能代替字体/阻焊的实际检查。

## 5. 检查失败无明细时不编造原因

原生 PCB DRC 可能返回“错误类别 → 网络 → 具体对象”的嵌套列表。包装器的 `violationCount` 可能只数顶层分组：本例一次历史检查包含 1 个分组、4 条 VBUS 断连。保留原始返回，明确统计层级，不把分组数当实际错误数。旧 DRC 与较晚保存源不能拼成当前通过/失败结论；修正后的状态需要同一版本快照对应的新检查。

本机 `sys.runDrc {type:'sch'}` 调用 `sch_Drc.check(true,false,true)`；声明应有详细结果，但当前原理图再次实测只返回 `false`，同时间段日志为空。记录检查未通过/原因未取得；既不能宣布通过，也不能由一个布尔值断言某个硬件接法错误。

2026-09-09 在 PCB6（EDA 3.2.121、实际桥接1.2.15）进一步核对已安装实现：SCH 路径丢弃 `includeVerboseError`，严格布尔结果也包含警告；详细条目进入 `schDrcLog`，公开 `SYS_Log` / `sys.getLogs` 读取的是另一份 `Log`。因此普通日志为空不能证明 ERC 无错误，历史供应商警告也不能解释当前 false。当前公开接口未验证到完整的无界面明细读取方式，勿为此循环重启、改规则或反复索要截图。换版本重新核对能力；当前 PCB DRC、原理图逐脚重建与未知 SCH 明细分别记录。证据索引见 [PCB6交付案例](replacement-and-delivery.md#证据索引与复用边界)。

读取日志时按本次时间、当前页身份筛选；旧 PCB 页的错误不能移作当前 SCH 的原因。空网引脚和显式 NC 状态分开读回，未标 NC 可作为待查线索，不能认定为无明细失败的唯一原因。

本例最终状态是 **PCB 原生 DRC 通过、网表一致、实际线路连通检查通过；SCH 原生检查完整验收未确认**。功能、负载、温升、制造文件、实板验证也单独报告，不用这块板的检查通过数宣传量产能力。

这段历史总结不能替代实际检查工件。只取得部分中间文件，或没有与当前保存版本对应的后续原生检查时，应报告当前验收未确认；不能引用本说明的“最终通过”补齐缺失证据。

## 历史证据与复用边界

下表概括当时使用的私人证据类型及其范围，原文件未公开，仓库不包含这些板级工件。它说明结论如何受到证据约束；复用方法时应为当前工程重新取得对应数据，不能据本文宣告新设计合格。

| 历史证据类别（未随仓库发布） | 当时核对的事实 |
|---|---|
| 原生保存源与布线读回快照 | 保存源与 getter 几何/单位/尺寸差异。 |
| USB 局部修复与端点对齐记录 | USB 局部换线换孔与精确端点对齐过程。 |
| 修复各阶段的原生 PCB DRC 返回 | 重写网络未解四处断开 → 对齐后通过 → 重铺铜后仍通过。 |
| 原生 USB 封装源 | 实际 USB 定位孔及完整封装图元。 |
| 独立铜连接与原生网表审查 | 独立检查范围、源哈希、网表、特殊焊盘及几何约束；不覆盖实板性能。 |
| 实际铜预览审查 | 实际 POURED、圆弧/孔洞支持、可见属性与源尺寸审计。 |
| 原理图检查返回与对应时段日志 | SCH false、错误数未知且该次无新增日志。 |

含私人目标与对象 ID 的历史工程脚本未随仓库发布，也未被转换成通用 skill 脚本。复用算法需先分离输入与执行、验证单位及对象支持；不要重跑未知来源的旧批量写入文件。
