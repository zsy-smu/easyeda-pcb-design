# 后台接口与本机经验

本文中的板号是历史案例代号。相关私人原工程、实物、截图、安装包摘录、运行快照和检查报告不随仓库发布；下文保留排障方法与当时的验证边界，不提供这些材料的公开复现入口。

## 连接与写入

复用已连接的 MCP/扩展/API。先查工具目录、桥接代码与只读状态；不要因为 GitHub 文档就启动另一服务、抢端口或换插件。

后台 API 不依赖鼠标位置，未必依赖前台窗口。失败时区分进程、扩展、WebSocket、活动页和能力；“最小化”检测或无截图不能证明后台不可操作。

写入批次前、重连/切页后核对工程和文档 ID/类型；同名不足以确定目标。依赖当前页的操作串行。记录 EDA、实际加载扩展、协议、已验证命令和单位；磁盘新包不等于已加载版本。

- 按真实类型选择元件、线、过孔等修改/删除 API；先 await 类型查询，不对 Promise 作类型判断。
- 读现值后合并修改并等待完成；异步 setter/`done()` 按当前定义执行，读回最终状态。
- 逐接口确认单位。原生 PCB/SCH 坐标可能差十倍，包装器可能已转 mm；不同对象角度可能分别用弧度和度。
- 移位置不应丢库、封装和 BOM。核对属性合并/替换语义，不把可能转换过单位的完整焊盘读回直接写回。
- 空集合也可能是错页、未稳定或接口不支持；用现有对象基线核对，不能直接判定没有对象。
- 创建超时先查实际对象，确认未完成再重试。日志记录请求 ID、目标、对象 ID 和完成状态。
- 诊断后仍不可用的接口改查已验证替代或源码；延长超时、反复重启/导入不是通用修复。

## 导线、网表与导入

本机审计发现某些 SCH getter 的扁平数组每四数表示独立线段，而 setter 的扁平数组表示连续折线。按实际接口结构逐段转换，不直接透传或跨版本猜测。

端口/flag 通过当前版本支持的锚点或短引线连接；坐标重合不证明电气连接。最终读回引脚网络。

网表先识别格式。本机见过新版 `components[uid].pinInfoMap` 与旧格式不同，误读会得到全空。空网引脚不能合并，别名需核实。

区分导入已发起、对话框待确认、已应用、已保存。用户已点击后用新的原生检查判断，不反复索要截图；真有界面步骤时先完成后台准备，再说明具体操作。

2026-09 本机曾出现公开引脚网络已对齐但仍有一条原生网表一致性错误；原生导入完成后消失，公开网表字节和几何未变。只记录现象，不断言缓存或某内部字段必然是根因。

PCB6 另一次发生在替换已关联的 USB 器件后：引脚网一致，但新实例缺失原关联字段。恢复经旧实例与原理图核对的 Channel ID 后，保存并重新运行原生 PCB DRC，结果为0。遇到同类现象先查身份/属性与端点两类差异；不要反复导入或随意生成 Channel ID。完整步骤与隐藏属性陷阱见 [器件替换与交付核对](replacement-and-delivery.md)。

## 在当前环境发现接口

历史环境的私人安装路径和客户端文件已省略。按下表发现当前环境的实际入口，不把示例目录、旧端口或历史客户端作为强制依赖；不存在则继续发现可用工具，不自动安装。

| 应发现的信息 | 核验方式 |
|---|---|
| 已配置的 MCP/桥接入口 | 从当前工具目录和服务配置确认入口、服务身份、WebSocket 地址与协议，不复用未经核对的旧端口。 |
| 当前客户端或调用封装 | 先读导出函数和请求格式，再确认与正在运行的服务兼容。 |
| 对应版本的 API 资料 | 核对资料与实际接口版本；名称相近的网关可能使用不同协议。 |
| 当前任务的快照与检查记录 | 核对捕获时间、工程身份和输入哈希，不直接运行历史修改脚本。 |
| 当前任务的交付目录 | 使用用户提供或本次任务产生的文件，不把历史案例摘要当作当前设计证据。 |

本机观察到的风险仅供排障：

- SCH `otherProperty` 可能整份替换，需保留原字段；与 PCB 行为分开核对。
- 全局焊盘与元件内嵌焊盘读回曾有角度/钻孔单位差异，用全局几何与封装资料交叉核验。
- 创建独立铜 FILL 时，单个选中元件曾导致 FILL 成为其子对象、全局集合漏读；创建前清选择，之后查所属对象。
- VIA 部分修改曾清掉阻焊值；选已验证局部 setter 或保留必要状态，逐字段复查。
- 部分网表 API 不完成，导入只报发起；声明工具存在不等于当前版本已验证成功。
- 当时无已验证的原生泪滴创建方法，导出枚举有 teardrop 不证明可创建。

新环境先只读核对，必要时在可恢复副本做最小能力验证。历史记录不是当前对象存在、连接正常或 DRC 通过的证据。

## PCB4 已验证案例（EDA 3.2.121 / 桥接 1.2.4）

- 原生 PCB 菜单为“设计 → 从原理图导入变更”，对话框按钮是“应用修改”。用户确认完成后读回 35 个器件的 Channel ID 和原生 DRC；本例网表一致性错误归零。菜单名称需按版本核对，不让用户寻找不存在的“导入”按钮。
- 导入后的某条 GND 直线被拆成两个新 ID。替换旧布线前，用网络、层、线宽及精确子线段几何确认归属，保存基线；不能把所有陌生 ID 一律删除，也不能认为 ID 改变必然代表用户新增走线。
- `getDocumentFootprintSources` 本例返回空，但原生自动备份 EPRU 含完整工程封装。封装入口图元与 Layer 48 壳体可用于独立核对端子方向、文字遮挡和装配空间；空返回不证明无封装。
- 本例翻转九个侧边端子时保留元件中心、引脚编号、网络及所有 BOM/库属性，重布线后核验 95 个焊盘、14 个网络、两层实际覆铜和原生 DRC。不要只转符号而保留旧引线或旧正极标记。

### 板框可见但Gerber预检不识别（同版本，已修复）

公开SDK的 `TPCB_LayersOfLine` 允许 `BOARD_OUTLINE=11`，但本机 `checkBorderBeforeGerber → Rze()` 只扫描矩形、圆、多边形三种管理集合，不扫描独立LINE。PCB4的4个LINE已闭合且DRC为0，仍触发“该PCB没有板框层线条”警告。因此“API允许放到某层”不证明导出器支持该图元。

遇到同样提示，先核对当前文档、板框真实类型和当前导出器支持的对象集合；相同提示不能单独证明是同一原因。

本例已验证修复：在11层用公开 `pcb_PrimitivePolyline.create` 创建同尺寸、空网络、首尾闭合的轮廓，读回确认原生POLY/公开Polyline后，按真实类型删除旧4个LINE；其他对象比较不变，重建覆铜、保存后DRC仍为0，单次Gerber生成返回成功。本桥接 `pcb.drawPolyline` 不自动闭合，矩形需5点首尾重复；坐标与线宽仍使用其已核验的mil单位。

历史审查在该版本安装包的 PCB 实现中定位到 `Rze`、`Lb`、`polylines-create`、`n$e`，并在 UI 实现中核对 `checkBorderBeforeGerber` 调用；这些压缩符号只用于说明当时的排查过程。安装包摘录和私人板框导出报告不随仓库发布，读者需在自己的合法安装与当前工程中独立核验。这是版本相关经验，不把POLYLINE写成所有EDA版本的唯一合法板框。

该次桥接只提供 `success:true/hasFile:true`，未回传ZIP字节；报告为“生成接口验证成功”，不能升级成“GM1/钻孔内容检查通过”。后续需要制造文件时，再获取实际文件检查。
